# 13 — C++ deterministic kernel build (Phase 3)

Phase 2 is frozen (`50ea369` accepted). The JEV sidecar is not modified
further unless Phase-3 integration exposes an actual contract defect.
This document is the Phase-3 build sequence. Order is load-bearing:
**boundary validator first, risk/sizing last.**

```
Raw AnswerSet JSON
     |
     v
Parse (JSON only, no semantics)
     |
     v
Schema validation (exact fields, versions, pins, types, ranges)
     |
     v
Cryptographic validation (response_hash recompute + Ed25519 verify + key trust)
     |
     v
State/freshness validation (state_hash + decision_key + expiry; LIVE vs REPLAY)
     |
     v
JEVAnswerSetV3 (typed object)
     |
     v
Deterministic decision engine (vetoes, table, sizing, exits, kills)
```

Once the object crosses the boundary, the rest of the kernel **never parses
arbitrary JEV JSON again**. Everything downstream consumes the typed object.

## 13.0 The three inequalities (locked)

```text
cryptographic validity =/= semantic validity =/= decision authorization
```

- A valid signature on a semantically invalid artifact -> HOLD.
- A semantically valid artifact that fails state binding or freshness -> HOLD.
- A fully valid artifact still only *nominates*; the deterministic engine
  authorizes (row-0 veto, R-gates, max-gate for 2xR). JEV never authorizes.

## 13.1 JEV filter (the only place model answers enter C++)

`kernel/jev_filter.hpp` validates one signed, candidate-bound answer against
values the kernel owns (expected cid, symbol, feature hash, trusted public
key, clock) and returns `PASS_BASE`, `PASS_ELEVATED_ELIGIBLE`, or `HOLD` plus
a coded reason. It never returns a side, family or size. Order of checks,
each failing closed:

1. Parse (bounded, duplicate keys rejected) and envelope shape.
2. `contract` tag, then the candidate block: cid recomputed from the exact
   identity strings and compared to the kernel's expected cid; symbol,
   side, family and economics coherence (BUY: stop < entry < TP).
3. Feature hash and symbol bindings; answer family equals the candidate's
   proposed family.
4. `decision_key` recomputed field-for-field.
5. Response hash and Ed25519 signature over the canonical payload bytes.
6. Freshness: integer seconds, `expires_at = created_at + 60`, 60 s skew.
7. Answer ranges, then the doc 03 §3.2 table with the veto's engine inputs
   (`risk/engine_inputs.hpp`); the first HOLD wins.

Primitives (strict JSON, canonical JSON, SHA-256/512, Ed25519 verify,
Python-repr floats) live in `kernel/jev_wire.hpp`. Python and C++ are held
together by 32 committed vectors in `kernel/jev_vectors/`, generated by
`research/strategy/gen_jev_vectors.py` and asserted by
`kernel/tests/test_jev_filter.cpp` (part of `build.sh` and CI) and by
`research/tests/test_jev_filter.py`. The veto composition (row-0 veto ->
engine inputs -> filter, including case 29) is tested in `risk/test_veto.cpp`.
Nothing on the entry path requires an answer: with `filter = none` the
kernel never reaches the filter (build-gated).

The calibration gate is BUDGET-DEPENDENT: a breach holds every tier,
`insufficient` still allows the base tier, and `pass` is required for the
elevated 2xR tier (conviction `max` nominates it; the engine authorizes).

Confidence is quarantined: no accessor exists and no kernel path reads it
(grep-gated).

## 13.5 P3.5 — Risk engine, sizing, exits, kills (docs 04–06 order)

  is unchanged — it simply belongs to the correct phase.

Gate classes (so long evidence never silently serializes the build):
[correctness] = unit/fixture suites, deterministic, minutes;
[drill] = fault-injection or procedure runs against built slices;
[soak]/[operational] = wall-clock evidence (F 24 h feed soak, H2 30 d).
Sequencing rule: a slice's correctness + drill gates must be green before
the next slice's correctness work starts; soak/operational gates attach to
their slice but may complete overlapped with downstream slices. §4.5's
isolation row belongs to Phase 2.5 (research-plane gate), not P3.5.

Exit: §4.5 + §6.5 correctness/drill boxes checked (H1 closes P3.5).
Soak/operational evidence tracked per gate class, never retro-blocking.
